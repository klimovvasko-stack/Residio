# Residio

Residio — консольное приложение для учёта комнат общежития и проживающих в нём студентов. Проект предназначен для автоматизации заселения и выселения студентов, управления жилищным фондом и контроля занятости комнат.

**Автор:** Климов Василий Андреевич, группа 26-ИВТ-4-2

## Возможности

В проекте предусмотрены следующие основные возможности:
- хранение информации о комнатах, студентах и учётных записях в реляционной базе данных SQLite;
- регистрация новых студентов и авторизация пользователей с разграничением прав доступа по ролям (Администратор / Студент);
- управление комнатами: добавление, редактирование, удаление, просмотр списка всех комнат и фильтрация только свободных;
- заселение и переселение студентов с автоматическим контролем вместимости комнаты;
- выселение студентов из комнат;
- просмотр администратором списка жильцов конкретной комнаты и управление профилями студентов;
- просмотр студентом информации о своей текущей комнате и соседях;
- автоматическое развёртывание базы данных и наполнение тестовыми данными (seed data) при первом запуске.

## Предметная область

- **Комната (`Room`):** уникальный ID, фактический номер комнаты, этаж, максимальная вместимость.
- **Студент (`Student`):** уникальный ID, ФИО, учебная группа, ссылка на комнату проживания (может быть не заселён), ссылка на учётную запись.
- **Пользователь (`User`):** уникальный ID, логин, пароль, ссылка на роль в системе.
- **Роль пользователя (`UserRole`):** уникальный ID роли, название роли (`Administrator` / `Student`).

Задача системы — обеспечить удобный учёт студентов и отслеживание статуса комнат, а также исключить логические ошибки (например, заселение в переполненную комнату или удаление комнаты, в которой числятся жильцы) за счёт строгой валидации на уровне бизнес-логики и внешних ключей БД.

## Пользователи и роли

| Роль | Возможности |
|---|---|
| **Администратор общежития** | Просматривает все комнаты и свободные места, добавляет/изменяет/удаляет комнаты, просматривает жильцов комнаты, регистрирует, редактирует и удаляет студентов, заселяет и выселяет жильцов, добавляет новых администраторов. |
| **Студент** | Авторизуется в личном кабинете, узнаёт статус своего заселения, номер своей комнаты, этаж и список соседей по комнате. |

### Основные компоненты

- **`main.py`** — точка входа в приложение. Запускает главный цикл программы и распределяет пользователей по соответствующим ролевым меню после авторизации.
- **`database/`** — отвечает за физическое подключение к файлу `residio.db`, включение поддержки внешних ключей (`PRAGMA foreign_keys = ON`) и автоматическое развёртывание таблиц при первом запуске.
- **`models/`** — содержит дата-классы (`@dataclass`), которые служат типизированными контейнерами для передачи данных между базой данных, сервисами и интерфейсом.
- **`repositories/`** — изолирует все SQL-запросы (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) и преобразует строки БД в объекты моделей.
- **`services/`** — содержит ключевые бизнес-правила и проверки (например, запрет на уменьшение вместимости комнаты ниже числа уже живущих там студентов или запрет на удаление заселённой комнаты).
- **`ui/`** — отвечает за консольный ввод-вывод, отображение меню и перехват исключений (`try...except`) для вывода понятных сообщений об ошибках пользователю.

## Архитектура

Приложение спроектировано по классической многослойной (N-Tier) архитектуре:

```text
Пользователь
     │
     ▼
Presentation Layer (ui: консольные меню, чтение ввода, вывод данных)
     │
     ▼
Business Logic Layer (services: правила заселения, валидация, проверка ролей)
     │
     ▼
Data Access Layer (repositories: параметризованные SQL-запросы, маппинг моделей)
     │
     ▼
Database Layer (database / SQLite: хранение данных в residio.db, контроль внешних ключей)
```

| Уровень | Пакет | Назначение |
|---|---|---|
| **Presentation Layer** | `ui`, `main.py` | Взаимодействие с пользователем через терминал |
| **Business Logic Layer** | `services` | Проверка бизнес-правил и координация операций |
| **Data Access Layer** | `repositories` | Выполнение CRUD-запросов к базе данных |
| **Data Layer & Models** | `database`, `models` | Хранение данных в SQLite и структуры сущностей |

## Требования

Для запуска проекта необходимы:
- **Python 3.10+** (используется современный синтаксис аннотации типов `int | None`);
- **Git**.

Внешние библиотеки для базовой работы не требуются — проект использует стандартную библиотеку Python (`sqlite3`, `dataclasses`, `pathlib`).

## Установка и запуск

1. Клонируйте репозиторий и перейдите в директорию проекта:
```bash
git clone [https://github.com/klimovvasko-stack/Residio.git](https://github.com/klimovvasko-stack/Residio.git)
cd Residio
```

2. Запустите приложение:
```bash
python src/residio/main.py
```

При первом запуске программа автоматически создаст файл базы данных `src/residio/residio.db`, развернёт таблицы и заполнит их демонстрационными данными.

После запуска в консоли откроется главное меню:
```text
====================================
   Система общежития «Residio»
====================================
1. Войти в систему
2. Регистрация студента
0. Выход из программы
Выберите действие:
```

### Тестовые учётные записи (создаются по умолчанию)

| Роль | Логин | Пароль | Примечание |
|---|---|---|---|
| **Администратор** | `admin` | `admin123` | Полный доступ к управлению комнатами и студентами |
| **Студент** | `ivanov` | `pass1` | Заселён в комнату №101 |
| **Студент** | `volkova` | `pass6` | Не заселена (для проверки заселения) |

### Принудительный сброс и проверка базы данных

Для пересоздания таблиц из `schema.sql` и вывода текущего содержимого всех таблиц в консоль предусмотрен служебный скрипт:
```bash
python src/residio/database/init_db.py
```
